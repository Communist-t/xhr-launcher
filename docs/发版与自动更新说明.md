# xHR Launcher 发版与自动更新说明

## 一、整体链路

```
打 tag vX.Y.Z
   │
   ▼
GitHub Actions（windows-latest）
   ├─ 拉取匹配版本物料（物料仓 Release）
   ├─ dotnet publish 打绿色免安装 zip + sha256 + latest.json
   ├─ ① 推 GitHub Release（备份/海外）
   ├─ ② 建/取 Gitee 同 tag Release
   ├─ ③ 回填 latest.json 的 package_url 为 Gitee 下载直链
   ├─ ④ 上传 zip / latest.json / sha256 到 Gitee Release
   └─ ⑤ 回填后的 latest.json 补挂回 GitHub Release

客户端（xHR.exe）
   ├─ 启动 / 手动检查 → 拉 latest.json（Gitee 直链）
   ├─ 版本比对：远端 > 本地 → 弹窗推荐更新（可稍后再说，不强制）
   ├─ 下载 zip → SHA256 校验 → 解压暂存
   └─ 退出主程序 → helper 覆盖程序目录 → 重启
```

- **下载与更新清单走 Gitee**：国内访问稳定；GitHub Release 作为备份与源码归档。
- 更新为**推荐式**：检测到新版本每次启动弹窗提示，用户可跳过；不做强制拦截。

## 二、仓库与产物命名

| 项 | 规则 |
|---|---|
| 主程序 exe | `xHR.exe`（程序集名 `xHR`，产品名仍显示 x.HR） |
| 发布包 | `xHR_<版本>_win-x64.zip` |
| 校验文件 | `xHR_<版本>_win-x64.zip.sha256` |
| 更新清单 | `latest.json`（挂在 Release 附件） |
| 版本文件 | 包内 `version.json`（`launcher_version` 供客户端本地比对） |

## 三、GitHub 仓库配置（Settings → Secrets and variables → Actions）

### Secrets

| 名称 | 说明 |
|---|---|
| `GITEE_TOKEN` | Gitee 私人令牌，需勾选仓库 Release 读写权限 |
| `MATERIAL_TOKEN` | 物料仓私有时填只读 PAT；物料仓公开可留空（回退 `GITHUB_TOKEN`） |

### Variables

| 名称 | 示例 | 说明 |
|---|---|---|
| `GITEE_REPO` | `Communist-t/xhr-launcher` | Gitee 仓库 `owner/repo` |
| `GITEE_OWNER` | `Communist-t` | Gitee 用户名/组织名，拼下载直链用 |
| `MATERIAL_REPO` | `Communist-t/xhr-materials` | 物料仓，默认已填 |

## 四、latest.json 字段结构

```json
{
  "launcher_version": "0.1.1",
  "package_url": "https://gitee.com/<owner>/<repo>/releases/download/v0.1.1/xHR_0.1.1_win-x64.zip",
  "sha256": "小写十六进制，发布时由流水线计算",
  "size": 233537495,
  "release_notes": "本次修复残留进程冲突",
  "mandatory": false,
  "runtime_material_version": "rpa-matrix-1.0.0"
}
```

- `package_url`：流水线回填为 Gitee 直链；
- `sha256`：客户端下载后校验，损坏/篡改则中止更新；
- `mandatory`：当前仅记录，客户端不做强制拦截。

## 五、客户端配置

程序目录 `config.json`：

```json
{
  "api_base_url": "http://saas-ai.cn:8080",
  "update_manifest_url": "https://gitee.com/<owner>/<repo>/releases/download/v0.1.1/latest.json",
  "apps": []
}
```

- `update_manifest_url` 留空时，默认请求 `{api_base_url}/api/launcher/latest`；
- 走 Gitee 分发时填 Gitee Release 附件直链即可，不需要后端接口。

## 六、发版操作步骤

1. 更新 `build/version.json`：
   - `launcher_version` 改为新版本（如 `0.1.1`）；
   - `runtime_material_version` 确认与物料仓最新 tag 一致。
2. 提交源码：
   ```powershell
   git add .
   git commit -m "release: 0.1.1"
   git push origin main
   ```
3. 打 tag 并推送，触发流水线：
   ```powershell
   git tag v0.1.1
   git push origin v0.1.1
   ```
4. 在 GitHub Actions 查看 `build-release` 运行结果；
5. 到 Gitee Release 确认：zip、`latest.json`、`.sha256` 三个附件齐全；
6. 客户端启动后点"检查更新"验证比对与下载链路。

## 七、版本对应规则

- 主仓 tag `v0.1.1` ↔ `launcher_version=0.1.1`；
- 物料 tag `rpa-matrix-1.0.0` ↔ `runtime_material_version`；
- 子程序单独升级：先给物料仓打新 tag，再回主仓更新 `version.json` 的物料版本号。

## 八、回滚

- **程序回滚**：在 Gitee/GitHub Release 找到上一个版本 tag，下载对应 zip 解压覆盖；
- **更新清单回滚**：把 `latest.json` 的 `launcher_version` / `package_url` 指回上一个稳定包，重新上传到 Release 附件；
- **流水线失败**：旧版本客户端不受影响；暂存目录在下次启动时自动清理，已下载 zip 保留可复用。

## 九、注意事项

1. Gitee 仓库需先建好同名空仓，令牌要有该仓 Release 权限；
2. 更新包 zip 解压后必须是程序根目录内容（exe + apps + appr + version.json + config.json），不能多套一层文件夹；
3. 大体积物料包走双端 Release 附件；若后续附件体积受限，需改走对象存储并在 `latest.json` 填对象存储直链；
4. 物料仓目前仍在 GitHub，物料如需迁 Gitee，需同步调整流水线物料下载步骤。
